Hashing is a technique used to **map data of arbitrary size to fixed-size values**, usually to enable fast data lookup, insertion, and deletion. It’s commonly used in:

* Hash tables (e.g. `HashMap`, `unordered_map`)
* Data structures like sets and dictionaries
* Cryptographic algorithms
* Checksums and data integrity checks

# Key Concepts

| Term              | Definition                                                   |
| ----------------- | ------------------------------------------------------------ |
| **Key**           | The input to the hash function (e.g. a string, number, etc.) |
| **Hash Function** | Maps a key to an integer (hash code)                         |
| **Hash Code**     | An integer generated by the hash function                    |
| **Bucket**        | A slot in the underlying array where the data is stored      |
| **Collision**     | When two different keys map to the same bucket               |

---

# Hash Functions

A hash function should:

* Be deterministic: same input → same output
* Uniformly distribute input over the output range
* Be fast to compute
* Minimize collisions

# Examples

For simplicity, assume we have `m` buckets:

```java
int hash(String key, int m) {
    int hashCode = key.hashCode();
    return Math.abs(hashCode) % m;
}
```

In real systems, better functions (e.g. `MurmurHash`, `SHA`, `xxHash`) are used depending on context.

# Collision Resolution

Since multiple keys can hash to the same index, we need strategies to handle collisions.

## Separate Chaining

* Each bucket contains a list (linked list or dynamic array)
* Multiple keys can exist in the same bucket
* Pros: simple, handles load well
* Cons: may lead to degraded performance if chains grow

```text
Index 3 → [(“apple”, 1), (“grape”, 2)]
```

## Open Addressing

All elements are stored directly in the array. If a collision occurs, find another slot.

### Linear Probing

* Move to the next slot (i.e. `i+1`) until an empty one is found
* Susceptible to clustering

### Quadratic Probing

* Try slots using a quadratic function: `i, i+1², i+2², ...`

### Double Hashing

* Use a second hash function to determine the step size

```java
int h1 = key.hashCode() % m;
int h2 = 1 + (key.hashCode() % (m - 1));
int index = (h1 + i * h2) % m;
```

# Pros and Cons

| Strategy          | Pros               | Cons                          |
| ----------------- | ------------------ | ----------------------------- |
| Separate Chaining | Simple, flexible   | Requires extra memory (lists) |
| Linear Probing    | Cache-friendly     | Clustering issues             |
| Quadratic Probing | Reduces clustering | Still limited                 |
| Double Hashing    | Best distribution  | More complex, needs 2nd hash  |

---

# Load Factor

Defined as:

```
α = number of entries / number of buckets
```

* High load factor → more collisions → slower performance
* Typical strategy: resize (rehash) when `α > 0.7`

# Applications

* **Hash Tables / Maps / Dictionaries**
* **Symbol Tables** in compilers
* **Database Indexing**
* **Caching** (e.g., memoization)
* **Cryptographic Hashing** (SHA-256)
* **Bloom Filters**

---

# Limitations and Pitfalls

* Poor hash functions can cause clustering
* Load factor must be controlled
* Collision handling increases complexity
* Hashing is generally not order-preserving
