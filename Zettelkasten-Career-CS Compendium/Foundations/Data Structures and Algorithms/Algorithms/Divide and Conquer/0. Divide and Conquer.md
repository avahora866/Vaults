# Divide and Conquer Algorithms

**Definition**:
Divide and Conquer (D\&C) is a problem-solving technique where you:

1. **Divide** the problem into smaller subproblems.
2. **Conquer** the subproblems by solving them recursively.
3. **Combine** the solutions to solve the original problem.

This pattern is useful when the original problem can be broken into **independent** subproblems that are similar in structure to the original.

---

## Structure

```text
function solve(problem):
    if problem is small:
        return base case solution
    else:
        divide problem into subproblems
        solve each subproblem recursively
        combine subproblem solutions
        return final answer
```

---

## Key Characteristics

| Feature         | Description                                    |
| --------------- | ---------------------------------------------- |
| Problem Type    | Recursive and reducible                        |
| Subproblem Size | Typically halves each time (logarithmic depth) |
| Merge Step      | Often includes sorting, merging, or combining  |
| Performance     | Often better than naive solutions              |

---

## Time Complexity

Depends on the recurrence relation:

```text
T(n) = a·T(n/b) + f(n)
```

Where:

* `a`: number of subproblems
* `n/b`: size of each subproblem
* `f(n)`: time to divide and combine

Use the **Master Theorem** to solve this.

## Common Examples

| Algorithm                    | Purpose                     | Time                        | Notes                              |
| ---------------------------- | --------------------------- | --------------------------- | ---------------------------------- |
| Merge Sort                   | Sorting                     | O(n log n)                  | Divides list, merges sorted halves |
| Quick Sort                   | Sorting                     | Avg O(n log n), worst O(n²) | Partitioning around pivot          |
| Binary Search                | Search in sorted array      | O(log n)                    | Divides array in half each step    |
| Karatsuba                    | Fast integer multiplication | O(n^1.58)                   | Faster than grade-school O(n²)     |
| Closest Pair of Points       | Geometry                    | O(n log n)                  | Divide by x-coordinates            |
| Strassen’s Algo              | Matrix multiplication       | O(n^2.81)                   | Faster than naive O(n³)            |
| Fast Fourier Transform (FFT) | Polynomial multiplication   | O(n log n)                  | Recursive D\&C on polynomials      |

## Example: Merge Sort (Java)

```java
void mergeSort(int[] arr, int left, int right) {
    if (left >= right) return;

    int mid = left + (right - left) / 2;
    mergeSort(arr, left, mid);
    mergeSort(arr, mid + 1, right);
    merge(arr, left, mid, right);
}

void merge(int[] arr, int left, int mid, int right) {
    int[] temp = new int[right - left + 1];
    int i = left, j = mid + 1, k = 0;

    while (i <= mid && j <= right) {
        temp[k++] = (arr[i] <= arr[j]) ? arr[i++] : arr[j++];
    }

    while (i <= mid) temp[k++] = arr[i++];
    while (j <= right) temp[k++] = arr[j++];

    System.arraycopy(temp, 0, arr, left, temp.length);
}
```

---

## Strengths

* Often reduces time complexity significantly
* Natural fit for recursion
* Parallelizable (subproblems can run independently)

---

## Weaknesses

* Not always optimal (e.g. Quick Sort worst case)
* Requires stack space for recursion
* Merge steps can be expensive

---

## When to Use

Use Divide and Conquer when:

* The problem can be split into **smaller independent** parts
* Subproblems are **similar in structure**
* You can **combine** results efficiently

---

## Summary

| Step    | Description                                  |
| ------- | -------------------------------------------- |
| Divide  | Break into subproblems                       |
| Conquer | Solve subproblems recursively                |
| Combine | Merge the solutions to form the final result |
