# What is npm?

**npm** is the default package manager for Node.js. It allows you to:

* Install and manage third-party packages (dependencies).

* Define and manage project metadata like the project name, version, author, and license.

* Share your own code as packages to the npm registry for others to use.

---

# `package.json`

The `package.json` file is a crucial part of any Node.js project. It serves as the **manifest** for your project, containing metadata about the project and details about the packages (dependencies) it requires.

## Key Fields in `package.json`:

* **name**: The name of the project.

* **version**: The version number of the project (using semantic versioning).

* **description**: A short description of the project.

* **main**: The entry point to your application (the main file, usually `index.js`).

* **scripts**: A set of commands that you can run via npm (e.g., build scripts, test scripts).

* **dependencies**: A list of the packages that your project needs to run in production.

* **devDependencies**: A list of packages that are only needed during development (e.g., testing libraries, build tools).

* **author**: The author of the project.

* **license**: The license type for the project (e.g., MIT, GPL).

## Example of `package.json`:

```
{
  "name": "my-app",
  "version": "1.0.0",
  "description": "A sample Node.js app",
  "main": "index.js",
  "scripts": {
    "start": "node index.js",
    "test": "jest"
  },
  "dependencies": {
    "express": "^4.17.1",
    "lodash": "^4.17.21"
  },
  "devDependencies": {
    "jest": "^26.6.3"
  },
  "author": "John Doe",
  "license": "MIT"
}
```

In this example:

* The `dependencies` section includes `express` and `lodash`, which are required for running the app in production.

* The `devDependencies` section includes `jest`, which is only needed for testing during development.

# `package-lock.json`

The `package-lock.json` file is automatically generated when you install or update any dependencies using npm. It **locks** the versions of the dependencies and their sub-dependencies, ensuring that everyone working on the project installs exactly the same versions, regardless of when or where the installation happens.

## Key Points about `package-lock.json`:

* **Version consistency**: It ensures that the same versions of dependencies are installed across different machines, which helps prevent "works on my machine" issues.

* **Detailed dependency tree**: It records the entire dependency tree, including sub-dependencies (dependencies of your dependencies).

* **Speed**: It speeds up subsequent installations by keeping track of the installed package versions and avoiding redundant package resolution.

### Example of a `package-lock.json` snippet:

```
{
  "name": "my-app",
  "version": "1.0.0",
  "lockfileVersion": 1,
  "dependencies": {
    "express": {
      "version": "4.17.1",
      "resolved": "https://registry.npmjs.org/express/-/express-4.17.1.tgz",
      "integrity": "sha512-d4om6w6wUxoTbmvPqS01LUcW+rUv2jiL1w7G1N3bqCzClmTY4ybFptQpP61axcAAGQzB7iZ/pcQ2eIu5RG8XA==",
      "dev": false
    }
  }
}
```

This `package-lock.json` file ensures that `express@4.17.1` will always be installed in the project, even if you or someone else later installs it on another machine.

# `dependencies` vs `devDependencies`

In `package.json`, you have two main categories for dependencies:

## `dependencies`:

* These are the packages that your application needs to **run** in a production environment.

* They are essential for your application to work, so when you deploy your application, these packages will be installed.

   Example: If you're building a web app, you'd likely have packages like `express`, `lodash`, or `mongoose` as dependencies because they are required for the app's functionality.

   You can install a package as a dependency using the following npm command:

```
npm install <package-name> --save
```

*   
  (In newer versions of npm, the `--save` flag is not required since it's the default behavior.)

## `devDependencies`:

* These are the packages required **only during development** and are **not** necessary for running the application in production.

* They usually include tools like testing libraries, build tools, code linters, or bundlers.

   Example: If you’re using **Jest** for testing, you’d include `jest` as a `devDependency` because it's only needed during development.

   You can install a package as a development dependency using the following npm command:

```
npm install <package-name> --save-dev
```

## Example:

In the `package.json` example above:

* **Dependencies**:

  * `express` is a package needed to run the application, so it's placed under `dependencies`.

  * `lodash` is also needed to run the app, so it's in `dependencies`.

* **DevDependencies**:

  * `jest` is used for testing during development, so it's placed under `devDependencies`.

# Installing Dependencies

When you clone a Node.js project or start a new project, you typically need to install the project's dependencies.

To install all dependencies listed in `package.json`, run the following command:

```
npm install
```

*   
  **Installing production dependencies only**: If you're preparing for a production deployment and want to avoid installing development dependencies (like test libraries), you can run:

```
npm install --production
```

---

# `npm install` vs `npm ci`

* **`npm install`**: This installs all dependencies listed in your `package.json` file. It also updates `package-lock.json` if necessary.

* **`npm ci`**: This is a faster, more reliable option for installing dependencies, especially in CI/CD (Continuous Integration/Continuous Delivery) pipelines. It uses `package-lock.json` to install exact versions of dependencies and **doesn't modify** `package-lock.json`. It's designed for environments where you want a clean, consistent install with no surprises.

---

# Managing and Updating Dependencies

* **Updating a dependency**: To update a specific package to the latest version, use:

```
npm update <package-name>
```

*   
  **Removing a dependency**: To remove a package that is no longer needed, use:

```
npm uninstall <package-name>
```

# Summary of Key Concepts

| Concept | Description |
| ----- | ----- |
| **`package.json`** | The manifest file that holds information about the project, including its name, version, dependencies, scripts, and more. |
| **`package-lock.json`** | A file that locks the specific versions of dependencies and their sub-dependencies to ensure consistent installations across different environments. |
| **`dependencies`** | Packages needed for the application to run in production. Installed with `npm install <package-name>`. |
| **`devDependencies`** | Packages needed only during development (e.g., testing frameworks, build tools). Installed with `npm install <package-name> --save-dev`. |
| **`npm install`** | Installs all dependencies listed in `package.json`, including both `dependencies` and `devDependencies`. |
| **`npm ci`** | A faster, more consistent way to install dependencies, used in continuous integration environments. It uses the exact versions specified in `package-lock.json`. |

---

# When to Use `dependencies` vs `devDependencies`?

* **Use `dependencies`** for libraries and modules that are needed to run the application in production.

* **Use `devDependencies`** for libraries that are only needed during development, such as testing tools, build tools, and code quality tools.
